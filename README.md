# 数据处理流程设计网站

React 负责流程连接、参数编辑、状态检查和局部重跑入口；Go 负责工程校验、版本保存、实际执行、产物持久化和输出文件写入。

## 工程格式

统一使用 `dataflow.project/v1`：

- `nodes`：步骤及参数，参数只表示本步骤配置，例如文件路径、过滤字段和转换值。
- `edges`：实际数据依赖，只连接组件声明的数据端口。
- 后续新增处理组件时继续在 Go 的组件目录声明输入、输出和参数，React 自动读取同一份组件契约。

## 关键语义

- 首次加载不再白屏：Go 服务在同端口托管前端构建产物（`frontend/dist`，可用 `DATAFLOW_STATIC` 覆盖），直接打开后端地址即可编辑；组件目录的空端口列表保证序列化为 `[]` 而不是 `null`，前端对空端口同样做了防护，空工程、自带样例和带空端口的节点都能正常进入编辑。
- 后端接口暂时失败（组件目录、保存、运行请求）时不会清空当前画布；保存成功但运行接口失败也会保留刚保存的 revision 与已有产物，稍后可重试执行。
- 修改步骤后，前端沿数据边计算并高亮该步骤及所有后续失效范围。
- 局部重跑只执行起点及其数据下游，未受影响分支可复用既有版本化产物。
- 某步骤失败或共享上游本轮空产出（0 行是合法的成功结果）时，Go 把共享下游标记为 `blocked` 并删除其旧产物，前端数据面板不会展示旧成功数据冒充本轮输出。
- 每次运行后，数据面板给出修订执行对照：哪些步骤沿用原结果（参数与上游输入版本均未变）、哪些重新执行，并区分依据——局部重跑起点、本步骤参数变化、上游输入版本变化、两者皆变或连带重算，同时显示当前与上一版版本号。
- 保存后又做了未发布修改时，可点“撤回未发布修订”回到最近一次保存的 revision 与产物快照；“重新打开已保存版本”始终从服务端读取已保存工程。
- 启动前执行拓扑排序；循环、缺失参数和无效数据端口都会返回 422，运行器不启动。
- 保存有效工程时递增 revision；工程与产物落盘，重新打开后仍可执行或局部重跑。
- 转换步骤的输入端口支持多连接，可用于分支后汇合并在数据预览中检查实际行数。

## 启动

后端：

```bash
cd backend
go test ./...
DATAFLOW_ADDR=:8080 go run ./cmd/server
```

先构建前端（`cd frontend && npm run build`）后，后端会在 `:8080` 同时提供页面和 `/api`；也可用 `DATAFLOW_STATIC` 指定其它构建目录。

前端：

```bash
cd frontend
npm install
npm run dev
```

Vite 已把 `/api` 代理到 `http://localhost:8080`。默认页面包含文件输入、过滤转换、文件输出以及分支汇合示例。

## 验证

```bash
cd backend && go test ./... && go vet ./...
cd frontend && npm run build
```
