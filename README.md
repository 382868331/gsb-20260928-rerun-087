# 数据处理流程设计网站

React 负责流程连接、参数编辑、状态检查和局部重跑入口；Go 负责工程校验、版本保存、实际执行、产物持久化和输出文件写入。

## 工程格式

统一使用 `dataflow.project/v1`：

- `nodes`：步骤及参数，参数只表示本步骤配置，例如文件路径、过滤字段和转换值。
- `edges`：实际数据依赖，只连接组件声明的数据端口。
- 后续新增处理组件时继续在 Go 的组件目录声明输入、输出和参数，React 自动读取同一份组件契约。

## 关键语义

- 首次加载不再白屏：Go 服务在同端口托管前端构建产物（`frontend/dist`，可用 `DATAFLOW_STATIC` 覆盖），直接打开后端地址即可编辑；空工程、自带样例和重新打开的工程都能保存并执行。
- 修改步骤后，前端沿数据边计算并高亮该步骤及所有后续失效范围。
- 局部重跑只执行起点及其数据下游，未受影响分支可复用既有版本化产物。
- 某步骤失败时，Go 将后续步骤标记为 `blocked`，并删除其旧产物，前端数据面板不会展示旧结果冒充本轮输出。
- 每次运行后，数据面板给出分支复用说明：哪些步骤本轮重算（整流程运行 / 局部重跑起点 / 连带重算）、哪些步骤沿用旧产物（参数与上游版本未变）以及各自依据。
- 修订后的执行对照会区分重算依据：起点参数变化（`rerun_params`）、上游输入产物版本变化（`rerun_input`）、手动强制重跑（`rerun_forced`）、首次执行（`rerun_first`）与整流程重算（`rerun_full`）；未受影响分支标记为“沿用原结果”（`reused`）。
- 保存或运行成功会记录已发布快照；继续编辑后可通过“撤回未发布修订”一键恢复到该快照（工程与画布结果一并还原），“重新打开已保存版本”从磁盘重新载入 revision 与产物。
- 空端口列表（如文件输入没有输入端口）后端始终序列化为 `[]`，前端对 `null`/缺失端口同样兜底，空工程、空输出（0 行合法空表）节点均可正常进入编辑；空输出在数据面板明确标注，不会与失败或旧数据混淆。
- 共享上游、空输出与局部失败同时出现时，只接受本轮 `succeeded`/`reused` 产物，任何上游失败或阻断都会让下游 `blocked` 并清除其旧产物，前端不展示旧成功数据。
- 启动前执行拓扑排序；循环、缺失参数和无效数据端口都会返回 422，运行器不启动。
- 保存有效工程时递增 revision；工程与产物落盘，重新打开后仍可执行或局部重跑。
- 转换步骤的输入端口支持多连接，可用于分支后汇合并在数据预览中检查实际行数。

## 启动

后端：

```bash
cd backend
go test ./...
DATAFLOW_ADDR=:8080 go run ./cmd/server
```

先构建前端（`cd frontend && npm run build`）后，后端会在 `:8080` 同时提供页面和 `/api`；也可用 `DATAFLOW_STATIC` 指定其它构建目录。

前端：

```bash
cd frontend
npm install
npm run dev
```

Vite 已把 `/api` 代理到 `http://localhost:8080`。默认页面包含文件输入、过滤转换、文件输出以及分支汇合示例。

## 验证

```bash
cd backend && go test ./... && go vet ./...
cd frontend && npm run build
```
